## 4. Verification of Matching Logic & The "0 Gap Skills" Bug

### Empirical Investigation of Heuristic Thresholds
The service applies the following heuristic classification rules:
- $\text{Cosine Similarity} \ge 0.80$: **Verified Match**
- $0.65 \le \text{Cosine Similarity} < 0.80$: **Partially Supported Match**
- $\text{Cosine Similarity} < 0.65$: **Skill Gap**

**Are these thresholds empirically validated? NO.**  
They were chosen as intuitive approximations.

### Root Cause Analysis: Why Did the Test Produce 0 Gap Skills?
When tested against the 20 competencies of ESCO `artificial intelligence engineer`, the candidate's 21 technical skills produced the following exact cosine similarities via `BAAI/bge-small-en-v1.5`:

### Key Mathematical Finding: Dense Vector Semantic Baseline Leakage
1. In high-dimensional dense embedding space (`bge-small-en-v1.5`, 384 dimensions), **all computing, software engineering, and data science terminology resides in a tight sub-cluster**.
2. Unrelated computing concepts routinely exhibit a baseline cosine similarity between **0.62 and 0.76** (e.g., `resource description framework query language` vs `Large Language Models` = `0.737`; `visual presentation techniques` vs `Computer Vision` = `0.712`).
3. Because the threshold for `partially_supported` was set at $\ge 0.65$, **every single requirement crossed the threshold**, completely masking critical skill gaps like RDF/SPARQL, SDLC, BPMN, and Information Architecture.
4. **Conclusion:** Equating raw cosine similarity with candidate proficiency (`Foundational`) is scientifically invalid. Vector closeness measures topical relatedness in English vocabulary, not whether a candidate has demonstrated competence.

## 5. Training Requirements & Objective Feasibility Assessment

### Official Determination
```text
NO MODEL TRAINING OR FINE-TUNING VERIFIED
```

### Feasibility Analysis of Available Corpora

1. **ESCO v1.1.1 (European Commission):**
   - *Nature:* Graph ontology linking 3,039 occupations to 13,938 skills via `essential` and `optional` relations.
   - *Supervised Pairs:* **None.** It contains no candidate profiles, no resumes, and no candidate-to-skill gap ground truth.

2. **O\*NET 31.0 (U.S. Department of Labor):**
   - *Nature:* Occupational ratings tables (Knowledge, Skills, Abilities, Work Activities) with expert Importance and Level scores ($1.0 - 5.0$).
   - *Supervised Pairs:* **None.** It is a normative occupational benchmark database, not a candidate evaluation dataset.

3. **English Recruitment Job Descriptions (`lang-uk`):**
   - *Nature:* 141,897 raw job descriptions.
   - *Supervised Pairs:* **None.** No candidate resumes or gap annotations.

4. **Job-Resume Matching Dataset (`Shresth786`):**
   - *Nature:* 1,167 job postings with `clean_skills`, `education_text`, and `years_required`.
   - *Supervised Pairs:* **None.** Contains extracted job skills, but **no** candidate evaluation pairs or verified gap ground truth.

### Why Fine-Tuning Was NOT Performed
To train a model for "Candidate Skill Gap Prediction", one would need a dataset of:
$$\mathcal{D} = \{(\text{Candidate Skills}, \text{Target Occupation Requirement}, y \in \{\text{Match}, \text{Partial}, \text{Gap}\})\}$$
No authentic, non-synthetic dataset of this nature exists. Synthesizing random negative pairs (e.g., pairing random candidate skills with random ESCO skills and labeling them "Gap") would violate the user's mandatory rules:
- *"Do not create synthetic resumes or fabricated training examples."*
- *"Do not manufacture labels or negative candidate-job pairs."*
- *"If no legitimate supervised training objective exists, explain why training is not justified and retain pretrained inference instead."*

**Conclusion:** Deploying `BAAI/bge-small-en-v1.5` as a zero-shot semantic retrieval model and `Qwen2.5-1.5B-Instruct-4bit` for instruction generation is the scientifically honest and compliant approach.

## 7. Discovered Bugs, Discrepancies & Recommendations

### Discovered Deficiencies
1. **Uncalibrated Thresholds & Semantic Baseline Leakage:**
   A similarity threshold of $0.65$ falsely classifies unrelated IT terms (e.g. SPARQL, BPMN, SDLC) as "partially supported" with "Foundational" knowledge, creating 0 skill gaps.
2. **Disconnected Roadmap Milestones:**
   The `weeklyMilestones`, `actionItems`, and `projects` returned by the backend are static templates with hardcoded URLs, rather than structured outputs parsed from Qwen or dynamically grounded in verified catalog resources.
3. **Qwen Re-loading Latency:**
   `mlx_lm.load("mlx-community/Qwen2.5-1.5B-Instruct-4bit")` is executed inside `generate_qwen_roadmap()` on every request instead of being cached at the service class level, causing a 5–8 second delay per API call.
4. **Unconstrained LLM Hallucinations:**
   Qwen is not given the verified learning resources in its prompt, leading it to recommend arbitrary commercial courses (Coursera, Udemy, DataCamp).

### Recommended Implementation Roadmap (Pending User Approval)
1. **Calibrate Semantic Matching:**
   - Elevate the `verified_match` threshold from $\ge 0.80$ to $\ge 0.85$ (or require direct/canonical alias match).
   - Elevate the `partially_supported` threshold from $\ge 0.65$ to $\ge 0.78$ and require shared domain tokens.
   - Competencies below $0.78$ should be classified as genuine **Skill Gaps** with Priority 1 ranking.
2. **Structured JSON Output from Qwen with Resource Grounding:**
   - Pass the verified learning resources into Qwen's context.
   - Instruct Qwen to return structured JSON adhering to the `WeeklyMilestone` schema, linking exclusively to the verified catalog URLs.
3. **Class-Level Model Caching:**
   - Cache the loaded MLX model and tokenizer on `SkillGapService._qwen_model` to reduce response times from 8.2s to <1.5s.
4. **Empirical Benchmarking on Synthetic-Free Gold Set:**
   - Curate a non-synthetic evaluation set of 50 verified technical skill pairs to empirically establish cosine similarity bounds.
